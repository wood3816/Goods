# 川昇叫貨系統｜單機離線 PWA

> **版本：v1.0.0** · **介面語言：繁體中文** · **部署方式：GitHub Pages**

川昇叫貨系統是為日常進貨作業設計的輕量化漸進式網頁應用程式（PWA）。輸入貨品編號，即可查詢商品資料及實際照片，設定叫貨數量，最後把叫貨單**輸出成 PNG 圖片**，方便透過 LINE 等通訊軟體提供給供應商備貨。

本版採用**單機離線模式**：首次連線載入並完成快取後，可以在支援的瀏覽器離線使用。商品、照片與叫貨紀錄保存在使用裝置的本機資料庫，不需登入，也**不會自動跨裝置同步**。

## 主要功能

| 功能 | 說明 |
| --- | --- |
| 快速叫貨 | 輸入貨品編號（例如 `G001`），自動顯示商品名稱、照片、單位、供應商及參考庫存。 |
| 商品資料庫 | 查詢、新增、編輯及停用商品，為商品上傳實際照片。 |
| 叫貨清單 | **以商品照片與叫貨數量為主**，可增減數量、刪除商品；重複加入相同貨號會合併數量。 |
| 圖片式叫貨單 | 輸出 PNG 圖片；上方顯示供應商、日期與單號，各品項以照片、貨號及大字數量呈現。 |
| 圖片分享 | 可下載圖片，或在支援的行動瀏覽器呼叫系統分享選單，再自行選擇 LINE 等應用程式傳送。 |
| 歷史紀錄 | 儲存、查詢歷史叫貨單，並能依歷史單再次建立叫貨。 |
| 本機離線 | 使用 Service Worker 快取程式，IndexedDB 保存商品、照片與叫貨資料。 |
| 資料備份 | 手動匯出及匯入含商品照片、歷史單與設定的 JSON 備份檔。 |
| 手動更新 | 由使用者在設定頁檢查並套用更新，不執行強制自動更新。 |

> 首次建立資料庫時，系統含 9 筆初始商品基本資料（`G001`～`G008`、`G011`）；**不含實際商品照片**。請自行確認商品資料並上傳照片。

## 使用流程

1. 進入**商品庫**，確認商品資料，並為各貨號上傳實際照片。
2. 返回**快速叫貨**，輸入貨品編號，核對系統帶出的品名及照片。
3. 輸入數量，按下**加入叫貨清單**。
4. 在**叫貨清單**增減或移除品項，確認數量。
5. 產生**叫貨圖片預覽**，確認供應商、日期、照片與數量。
6. 下載 **PNG**，或使用行動裝置的分享功能傳送給供應商。
7. 視需要儲存歷史叫貨單，並定期匯出完整備份。

### 商品圖片存放在哪裡？

**v1.0.0 不需要在 GitHub 新建商品照片資料夾。** 商品照片透過系統「商品庫 → 商品詳情 → 編輯商品 → 上傳／更換圖片」新增，會壓縮並存入目前裝置的 **IndexedDB**，再透過貨品資料中的圖片 ID 對應。

- 支援一般 **JPG、PNG、WebP** 照片，單張上傳上限 **8 MB**。
- 照片上傳後，即可用於商品查詢畫面與 PNG 叫貨單。
- **尚未上傳實際照片**的商品，輸出時會標示缺少照片；不會自動產生或套用其他商品的示意照片。
- 將 `G001.jpg` 等檔案直接放到 GitHub 的 `assets/` 目錄，**本版不會自動以貨號載入**；若要這個功能，需另行開發。

### PNG 叫貨單格式

輸出內容以**商品照片與數量**為主要視覺，保留小字貨號供核對。叫貨單頁首包含供應商、日期和單號。每張圖片最多排 **13 項商品**；超過時會分成多張 PNG，請逐張確認及傳送。

## 使用技術

- HTML、CSS、原生 JavaScript（ES Modules）
- PWA Manifest、Service Worker
- IndexedDB 本機資料庫
- Canvas 產生 PNG 圖片
- GitHub Pages 靜態網站部署

此版本**不需要自行建立伺服器或雲端資料庫**。

## 部署到 GitHub Pages

1. 在 GitHub 建立一個新的 Repository，例如 `chuansheng-orders`。
2. 解壓縮完整 PWA 程式包，將**程式檔案與資料夾內容**上傳到 Repository **根目錄**，不要只上傳 ZIP。
3. 再把這份 `README.md` 上傳到**與 `index.html` 同一層**。
4. 開啟 Repository 的 **Settings → Pages**。
5. 在 **Build and deployment** 中選擇 **Deploy from a branch**，分支選 `main`，資料夾選 `/(root)`，按下 **Save**。
6. 等待部署完成，開啟 `https://<你的 GitHub 帳號>.github.io/chuansheng-orders/`。
7. 第一次請在有網路時載入完整程式；快取完成後再測試離線操作。

> 實際網站網址會依 Repository 名稱而不同。GitHub Pages 是靜態網站主機，不負責同步或永久備份 IndexedDB 使用者資料。

### 手機加入主畫面

- **iPhone／Safari**：開啟已部署網址 → 分享 → **加入主畫面**。
- **Android／Chrome**：開啟網站 → 瀏覽器選單 → **安裝應用程式**或**加入主畫面**（依裝置支援情況而異）。

## 備份、更新與注意事項

**資料安全**

- 商品、照片及叫貨紀錄都儲存在**目前裝置、瀏覽器與網站來源**對應的儲存空間。不同手機、電腦或瀏覽器的資料不會自動同步。
- 清除網站資料、移除應用程式或瀏覽器清理儲存空間，可能造成資料遺失；請定期於**設定 → 匯出完整備份（JSON）**建立備份並另存安全位置。
- 匯入備份可能覆蓋現有資料，應先檢查匯入內容，並在執行前另外備份目前資料。
- 現有庫存僅供參考；**建立叫貨單不會自動扣減庫存**。

**版本更新**

1. **先匯出完整備份**。
2. 將新版程式檔案部署到同一個 GitHub Pages 網址。
3. 透過系統設定頁手動**檢查版本**，依畫面提示套用新版。
4. 完成後確認叫貨資料、商品圖片及圖片輸出是否正常。

本版不使用強制自動更新，避免操作中途無預警重新載入頁面。

**已知使用限制**

- 必須使用 HTTPS（例如 GitHub Pages）或開發環境中的 `localhost`，才能正常使用 Service Worker；不建議直接用 `file://` 開啟 `index.html`。
- LINE 分享由手機系統的分享面板處理；**不是自動傳送給指定 LINE 聯絡人**。
- iOS／不同瀏覽器對多檔案分享或下載的支援不完全相同，多張 PNG 可能需要分次操作。
- 目前沒有會員權限、雲端同步、多裝置共用資料或自動讀取 GitHub 商品圖片的功能。
