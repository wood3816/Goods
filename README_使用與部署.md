# 川昇叫貨系統 v1.0.6 — PWA 程式包

## 系統功能

1. **快速叫貨**：輸入貨號（例如 `G001`），即時顯示品名、單位、目前庫存、供應商及已上傳的實物照。輸入數量後加入叫貨清單，同貨號數量合併。
2. **叫貨清單**：列表刻意簡化為「商品圖片、貨號與數量」，不顯示庫存、日期等非必要項目；數量可用 `−`/`＋` 調整。
3. **叫貨圖片（PNG）**：叫貨單可預覽並輸出為 PNG，供應商與叫貨日期列在上方；每項以完整實物照片（等比例置中、不裁切）、貨號與大字數量呈現。超過 6 項會自動輸出多張圖片。在支援檔案分享的行動瀏覽器可使用「分享圖片」叫出分享選單，選擇 LINE 並自行送出。
4. **商品資料庫**：新增、編輯、停用商品，所有顯示區塊自動等比例完整顯示商品照片（不裁切），上傳實際照片（JPG/PNG/WEBP，單張不超過 8MB）；照片保留原始長寬比例，最長邊超過 1400 px 時等比例縮小，JPEG 品質 86%，儲存於本機 IndexedDB，離線可看。
5. **歷史叫貨**：儲存單據後可查詢、重新叫貨；同一張單不會因重複點擊而產生兩筆。首次安裝含根據畫面建立的 9 筆商品基本資料。
6. **完整備份**：JSON 含商品、照片、歷史單據、供應商及未完成的清單。匯入前檢查格式、商品編號重複及數量，再由使用者確認是否覆蓋現有資料。
7. **離線可用**：Service Worker 快取網頁程式、IndexedDB 存資料。支援手機加入主畫面。
8. **手動版本管理**：設定頁有「檢查版本」；不會定時強制下載並重新整理、也不會自行 `skipWaiting()`。

## 首次操作

1. 先到「商品庫」查看 `G001`～`G008`、`G011`；這些商品初始**沒有實際照片**。
2. 點「查看」→「編輯商品」→「上傳／更換圖片」，為每個商品選擇實物照片。
3. 回「快速叫貨」，輸入貨號，確認圖片及名稱，填數量加入清單。
4. 在「叫貨清單」確認每項的照片與數量，設定供應商、日期，點「產生叫貨圖片預覽」。
5. 可先「儲存叫貨單至歷史紀錄」，再「下載 PNG 圖片」，或直接「分享圖片」給供應商。
6. 到「設定」執行完整 JSON 備份，定期備份到外接硬碟、電腦或雲端私人儲存空間。

## GitHub Pages 部署

1. GitHub 新增儲存庫，例如 `chuansheng-orders`。
2. 將本程式包資料夾裡的**所有檔案與資料夾**上傳到儲存庫根目錄；`index.html` 必須在根目錄。**不要直接上傳 ZIP 當作網站。**
3. 儲存庫進入 **Settings → Pages**，選擇 **Deploy from a branch**，選 `main`、`/(root)`，儲存。
4. 等 GitHub Pages 發佈後，開啟 `https://你的帳號.github.io/chuansheng-orders/`。
5. 第一次需要連線載入網頁；安裝完 PWA 並成功快取後，可離線使用。iPhone Safari 用分享選單 →「加入主畫面」。
6. 手機與電腦間**不會同步**：兩台裝置各有一份獨立 IndexedDB。需手動匯出與匯入 JSON 交換資料。

## 資料安全與使用限制

- 本專案未連接伺服器資料庫、沒有帳號系統，資料只留在**當前瀏覽器與當前網域**（主畫面 PWA 和 Safari 可能有不同的資料分區），請先測試備份還原。
- 清除網站儲存資料、移除 PWA 或瀏覽器的儲存回收機制，可能導致資料遺失；請定期備份。
- 系統庫存欄只提供參考，叫貨不會自動扣庫存、也不會自行認列進貨。
- 未有實物照片時，畫面與 PNG 會顯示「尚無商品照片」的明顯占位提示；絕不使用虛構商品圖冒充實物。
- 請用 HTTPS（GitHub Pages）或 `http://localhost` 測試；直接點開 `index.html` 的 `file://` 模式不能正常啟動模組／Service Worker。
- **更新**：請先完整匯出備份。上傳新版程式後至設定頁按「檢查版本」，待新版準備好再按「套用已下載新版」。程式不強制自動重整。若同時開啟多個分頁，請先關閉其他分頁。
- iOS Safari 不一定支援「分享多個檔案」或一次下載多張 PNG；多品項分頁時可分次下載或使用支援多檔分享的瀏覽器。
- 圖片輸出每頁至多 6 項（2 行 × 3 列），確保單張長圖不會過大。品項數很多時會產出多張圖片。
- **目前未製作雲端同步、權限管理、線上購物車或真正的直接傳 LINE API**（分享需使用者在裝置上確認）。

## 檔案結構

```text
index.html               主程式入口
manifest.webmanifest     PWA 設定
sw.js                    離線快取、手動套用更新
version.json             手動版本檢查
css/app.css              全裝置響應式樣式
js/app.js                頁面、互動、庫存、商品、訂單、備份
js/db.js                 IndexedDB 資料結構及範例資料
js/image.js              PNG 輸出／分享
assets/icon-192.png      手機主畫面圖示
assets/icon-512.png      PWA 圖示
assets/icon.svg          圖示可再編輯來源
README_使用與部署.md      本文件
設計參考_非程式實際畫面.png  前一回合核可的概念效果圖（非真實商品照片）
```

## v1.0.4 更新說明（2026-10-15）

- **圖片完整顯示**：快速叫貨、商品庫、商品詳情、編輯照片、叫貨清單、預覽單一律使用 contain 等比例置中，四邊保留，留白而不裁切。
- **PNG 叫貨單**：canvas 輸出同樣依原比例計算可用範圍，所有邊緣完整顯示，保留小幅四周邊距。
- **圖片匯入**：限制 8MB，長邊最高 1400 px，等比例調整，不裁切源圖。若「原始照片本來就被裁切」，系統無法自動補回缺少的部分。
- **無破壞性資料變更**：IndexedDB schema 與資料庫名稱皆不變；既有商品、照片、歷史單與草稿原地保留。
- **手動更新**：不加入自動重整或強制跳版，請在設定裡檢查並手動套用。

## v1.0.4 圖片快速上傳（新增）

1. 在商品資料庫找到要更新的品項，例如 `G001`。
2. 直接點左側縮圖（含「圖片待上傳」框），不必點「查看」或「編輯」。
3. 從手機相簿／電腦選擇商品照片，選取後自動縮放並儲存，完成後商品圖立即更新。

也可以在商品詳細資料頁直接點大圖；原編輯頁的「上傳／更換圖片」仍然可用。照片只存於目前瀏覽器，不會上傳到 GitHub。

**遇到失敗：** 上傳被取消、照片格式無法解碼或儲存失敗時，原照片不會被刻意清除；如有問題請先保留備份，不要清除網站資料。

## v1.0.4 歷史紀錄刪除

- 單筆：歷史紀錄 → 該訂單右側「⋯」→ 刪除此筆紀錄 → 確認刪除。
- 多筆：歷史紀錄 → 多選刪除 → 勾選指定訂單 → 刪除選取 → 確認。
- 搜尋文字變更會清除目前勾選，以免刪除不在畫面中的訂單。
- 刪除採用單一 IndexedDB 交易；只刪歷史訂單，不變動商品、照片、供應商及目前叫貨清單。
- 刪除無內建復原功能；執行前建議先從設定匯出完整 JSON 備份。


## v1.0.6 叫貨單 PNG 宮格版

1. 輸出時每張固定為 **2 行 × 3 列**，每頁最多 6 項，超過自動分頁。
2. PNG 每頁寬 **1800 px**，每項維持 **450 × 420 px** 的大圖片顯示區，不裁切。
3. 每張均帶公司 LOGO、供應商、日期、單號、頁碼及本張合計；品項顯示照片、貨號、品名與數量。
4. 預覽和輸出使用相同的分頁規則，7 項分 2 張、13 項分 3 張。
5. 升級前請匯出本機資料備份，且不要刪除 iPhone 主畫面 PWA 或清除 Safari 網站資料。
